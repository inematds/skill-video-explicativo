🧩 What is a Skill

From first principles: one folder, one SKILL.md file, and packaged knowledge that teaches Claude to do something specific.

What it is:

A Skill is a folder whose name is the skill's name, containing a file SKILL.md. This file is all that's needed for the skill to exist.

Why learn:

It's the basic building block. Once you understand the folder+file, everything else (refs, scripts) is just an optional addition.

Key concepts:

Folder = identity; SKILL.md = instructions; nothing else is required.

What it is:

The skill packages an entire procedure—steps, rules, examples—that Claude follows consistently every time.

Why learn:

Instead of re-explaining a workflow in every conversation, you save it once and it stays reusable.

Key concepts:

Reuse, consistency, lasting knowledge.

What it is:

The body of SKILL.md is ordinary Markdown: headings, lists, code blocks. Claude reads it as instructions to follow.

Why learn:

You write in the same format you already use to document things — no new language required.

Key concepts:

Markdown, clear instructions, numbered steps.

What it is:

A prompt lives in a conversation and disappears. A skill stays on disk, can be versioned, and triggers automatically when the task matches.

Why learn:

Knowing when to promote a repeated prompt to a skill saves hours.

Key concepts:

Ephemeral vs. durable; manual vs. automatic.

What it is:

Skills can create videos (HyperFrames), review code, design interfaces, generate diagrams — any repeatable workflow.

Why learn:

Seeing the variety opens your mind to what’s worth turning into a skill for your day-to-day work.

Key concepts:

Repeatable workflows, varied domains, this course originated from a skill.

What it is:

Creating the simplest skill doesn’t require programming: just describe the procedure in text.

Why learn:

Removes the barrier to entry — anyone who writes well can create a useful skill.

Key concepts:

Low barrier to entry; start with text and expand later.

📝 Anatomy of SKILL.md

Every SKILL.md starts with two lines: name and description. The description is what Claude reads to decide when to use the skill — it's the trigger.

What it is:

At the top of the file, between --- e ---, the YAML metadata goes here: at least name e description.

Why learn:

This is the only part always loaded into Claude's memory. Getting this wrong breaks the skill.

Key concepts:

YAML, delimiters ---, metadata.

What it is:

O name is the skill identifier (kebab-case), usually the same as the folder name.

Why learn:

This is how you and Claude refer to the skill when invoking it.

Key concepts:

kebab-case, unique, same as the folder.

What it is:

A description says WHAT the skill does and WHEN to use it. This is the text Claude consults to decide whether to invoke the skill.

Why learn:

Weak description = the skill never triggers. This is the highest-impact item in SKILL.md.

Key concepts:

Triggers, “use when…”, specificity.

What it is:

A good description lists concrete trigger phrases ("use when the user asks for a video, explainer video, Shorts…").

Why learn:

The closer it is to how the user speaks, the more reliable the trigger.

Key concepts:

Trigger phrases, synonyms, cover variations.

What it is:

After the frontmatter comes the body: the procedure, rules of thumb, commands. This is what Claude runs when the skill is triggered.

Why learn:

This is where the skill's real value lies — the clearer it is, the better the result.

Key concepts:

Ordered workflow, non-negotiable rules, links to references.

What it is:

Forget a ---, incorrect YAML indentation or a description that's too vague are the most common errors.

Why learn:

Recognizing the symptom ("my skill doesn't trigger") saves debugging time.

Key concepts:

Delimiters, indentation, specificity.

🧠 Progressive disclosure

The key concept: Claude doesn’t load everything at once. Name and description are always in memory; the rest loads only when needed.

What it is:

Claude’s context window is finite. Loading dozens of entire skills at once would fill it up.

Why learn:

Understanding the limitation explains why progressive disclosure exists.

Key concepts:

Context window, cost, scale.

What it is:

Only the name and description of each installed skill are always visible to Claude—lightweight and inexpensive.

Why learn:

Explains why the description needs to be so good: it's the only signal that's always present.

Key concepts:

Always-on, skills index, lightweight.

What it is:

When the task matches the description, Claude opens the full contents of SKILL.md.

Why learn:

This is when the detailed instructions come into play — on demand.

Key concepts:

On match, on-demand loading.

What it is:

Reference files and scripts are read only when SKILL.md points to them and the step requires them.

Why learn:

Lets you package a lot of large materials at no cost until they’re used.

Key concepts:

On demand, references, executable scripts.

What it is:

You can have dozens of skills installed and keep the context lightweight, because only the index is always present.

Why learn:

This is what makes a large skill library viable without performance loss.

Key concepts:

Scale, efficiency, large library.

What it is:

Claude compares the user's request with the available descriptions and chooses the most relevant skill.

Why learn:

Knowing this helps you write descriptions that “win” the right match.

Key concepts:

Matching, relevance, priority.

📂 Where they live & how to install

Skills live in .claude/skills — in the project (only there) or globally (anywhere). Installing means copying the folder or running a command.

What it is:

One folder .claude/skills/ inside the repository makes the skill available only in that project.

Why learn:

Ideal for product-specific skills, versioned alongside the code.

Key concepts:

Project-scoped, versioned, specific.

What it is:

The global folder in your home (~/.claude/skills/) makes the skill available in any project.

Why learn:

Perfect for personal skills you use all the time, such as the one for videos.

Key concepts:

Global, reusable, personal scope.

What it is:

Because it’s just a folder, installing it can literally mean copying and pasting it to the right location (or extracting a zip).

Why learn:

This is how you received the skill for this course — a zip file containing the folder.

Key concepts:

Copy the folder, zip file, no installer.

What it is:

There are command-line tools that install skills from a catalog with a single command.

Why learn:

Faster and more consistent when the skill is published in a registry.

Key concepts:

CLI, catalog, one command.

What it is:

Because skills are text files, they go into git like any code — with history and review.

Why learn:

Lets you evolve the skill safely and roll back if something breaks.

Key concepts:

Git, history, review.

What it is:

Adding the skill to the project repository delivers it ready for the whole team, with the same behavior.

Why learn:

Standardizes how the team uses Claude and spreads best practices.

Key concepts:

Team, standardization, organizational scale.
