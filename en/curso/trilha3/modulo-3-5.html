🎚️ Instructions vs. layout — BOTH levels

All visual customization of a HyperFrames video happens in two distinct places with completely different scopes. Confusing the two is the main reason changes "disappear" or "affect everything unintentionally." Understanding the model is the first step.

1
Instruction (global) ~/.claude/skills/video-explicativo/

The skill installed in your Claude Code environment. Contains two files that define the default for every new video that Claude should generate from now on:

references/house-style.md
Mood, palette, fonts, aspect ratio, composition rules. All in prose. Claude reads and interprets it when generating the build-index.mjs.
scripts/composition-template.mjs
The code template with complete CSS, classes (.title, .h2, .scene…), 9:16 overrides and scene structure.
2
Layout (local) projeto/build-index.mjs

The copy generated in the specific project. This is the concrete CSS/HTML for that render. Editing it affects only that video — fast, with no global consequences.

Golden rule
Modify the instruction changes everything going forward (all new videos). Change the layout changes only that video.
💡
Practical tip
Before editing any file, ask: "I want this to change in all the next videos or just this one?" If the answer is "just this one," touch only the build-index.mjs from the project. If it’s "everywhere," edit the installed skill — and remember to commit and publish it to repo da skill.
Key concepts
Instruction
house-style + template = global standard
Layout
build-index.mjs = concrete local CSS/HTML
Scope
global vs. local — always decide first
Repackage
required when changing the installed skill

🔠 Element sizes

O composition-template.mjs defines base sizes for 16:9. There's a 9:16 overrides block (prefix body.v) that resizes everything for vertical. Knowing the classes and concrete values lets you make precise adjustments.

Base sizes — 16:9 (composition-template.mjs)
Class Property 16:9 value 9:16 override
.title font-size 172px 118px
.h2 font-size 92px 74px
.lead font-size 34px 30px
.folder width / height 520px / 360px 440px / 300px
.code width auto 940px
.file-card font-size / top / left 36px / 120px / 110px 30px / 110px / 96px
.subhead font-size 40px 34px
Actual block from composition-template.mjs — base 16:9 classes
/* composition-template.mjs — typography and base cards */
.title{font-family:Sora,sans-serif;font-weight:800;font-size:172px;line-height:.95;letter-spacing:-.03em;margin:24px 0}
.subhead{font-size:40px;color:var(--muted)}
.h2{font-family:Sora,sans-serif;font-weight:800;font-size:92px;line-height:1.05;letter-spacing:-.02em}
.lead{font-size:34px;color:var(--muted);margin-top:28px;line-height:1.4}
/* folder */
.folder{position:relative;width:520px;height:360px;margin:0 auto}
/* 9:16 overrides */
body.v .title{font-size:118px;margin:20px 0}
body.v .h2{font-size:74px}
body.v .lead{font-size:30px;margin-top:24px}
body.v .folder{width:440px;height:300px}
🔼
How to enlarge an element
Locate the class in the build-index.mjs from the project and increase the value. For .title from 172px → 200px, for example:
- .title{font-size:172px}
+ .title{font-size:200px}
/* and the 9:16 override, if you want to keep the aspect ratio: */
- body.v .title{font-size:118px}
+ body.v .title{font-size:138px}
Key concepts
Base 16:9
default values for the horizontal template
body.v
prefix that activates 9:16 overrides
Aspect ratio
base adjustment and override on the same scale
Find
grep the class before editing

📐 Safe margins

O .scene is the container for each scene. Its padding defines the space between the content and the edge of the frame — the "safe margin." Decreasing it = full-bleed; increasing it = more breathing room.

16:9 (landscape)
.scene{
/* top right bottom left */
padding:120px 150px 150px;
}
Top 120px, sides 150px, bottom 150px. Good balance for 1920×1080.
9:16 (vertical / Shorts)
body.v .scene{
/* top right bottom left */
padding:170px 70px 240px;
}
Top 170px (camera face), sides 70px, bottom 240px (thumb + UI). Never reduce the bottom below 180px in Shorts.
Captions have their own margin — separate from .scene padding
.caption{bottom:64px} /* 16:9 */
body.v .caption{bottom:150px} /* 9:16 — above the UI bar */
When reducing the padding of the .scene to go full-bleed, the caption may spill out. Adjust .caption{bottom} proportionally.
⚠️
Attention: invisible overflow
Reducing the padding too much can cause elements to go off-canvas without you noticing in the preview. Always run npx hyperframes inspect --samples 16 after changing margins. The audit will report overflow if it detects content outside the bounds.
✓ Best practices
  • ✓ Keep bottom ≥ 120px in 16:9
  • ✓ Keep bottom ≥ 180px in 9:16 (Shorts UI)
  • ✓ Adjust .caption{bottom} when changing padding
  • ✓ Run inspect after every change
✗ Avoid
  • ✗ Zero or negative padding
  • ✗ Ignore the caption when going full-bleed
  • ✗ Change only 16:9 and forget the 9:16 override
  • ✗ Publish without running inspect
Key concepts
.scene padding
120/150/150 (16:9) · 170/70/240 (9:16)
.caption bottom
64px 16:9 · 150px 9:16
overflow
invisible in preview, visible in inspect
full-bleed
reduces padding but always validates

🏷️ Brand position

Sometimes you want a persistent brand element — a logo, watermark, badge — that appears in all the scenes without getting into scene/tween logic. The pattern is to add this element to .bg-layer (persistent background layer) with data-layout-ignore and position it with CSS, using the override body.v for vertical.

ℹ️
The CTA already exists — don’t reinvent it
The final scene (scene9) always displays the CTA INEMA.CLUB as the mandatory closing for the video. It covers the "final brand mark." The persistent element we're creating here serves to subtle identification during the video — like a corner watermark.
Snippet: persistent brand element in .bg-layer
/* build-index.mjs — inside .bg-layer, after the existing elements */
/* 1. Add the element with data-layout-ignore */
<div id="brand-mark"
data-layout-ignore="true"
style="position:absolute;bottom:40px;right:50px;opacity:0.35;pointer-events:none;">
<img src="brand/logo.svg" width="120" alt=""/>
</div>
/* 2. CSS: base position (16:9) + 9:16 override */
#brand-mark{
position:absolute;bottom:40px;right:50px;
opacity:.35;pointer-events:none;
}
body.v #brand-mark{
/* 9:16: brand at the top, centered */
top:60px;bottom:auto;left:50%;right:auto;
transform:translateX(-50%);opacity:.45;
}
🔑
Why data-layout-ignore is required
The HyperFrames auditor measures each element's bounding box to detect overflow. A brand element outside the default bounds will trigger a false positive — unless you mark it with data-layout-ignore="true". With this attribute, the auditor ignores the element when counting overflow.
Key concepts
.bg-layer
persistent layer — appears in every scene
data-layout-ignore
excludes from the overflow audit
body.v override
different position in 9:16 (centered at the top)
scene9 CTA
INEMA.CLUB is already the ending — don’t duplicate it

🔁 One-off vs. permanent

Before making any edits, decide the scope. The question is simple: does this change apply only to this video or for all the next? The answer determines which file you edit — and how much work it will take.

P One-time — 1 video
Edits the build-index.mjs from the project and renders it again.
✓ Fast — 1 file, 1 render
✓ No risk of affecting other projects
✓ Doesn't require repackaging the skill
✗ The next video doesn't inherit the change
When to use
  • • Fine-tune the color for a campaign
  • • Test a new card layout
  • • Font override for a client
  • • Aspect ratio correction in a specific frame
G Permanent — all
Edits house-style.md + composition-template.mjs in the installed skill and repackages.
✓ All new videos inherit
✓ Maintain brand consistency
✗ Requires a commit + push to the skill repo
✗ More impact — test first
When to use
  • • Change the channel’s color palette
  • • Adopt a new default typeface
  • • Add a brand element to all
  • • Adjust global safety margins
Decision grid: which file should you edit?
Status build-index.mjs house-style.md composition-template.mjs
Change the color of just one video ✓ — —
Change the default font for all of them — ✓ ✓
Increase .title in this project ✓ — —
Increase .title in all videos — — ✓
Add a persistent global brand element — ✓ ✓
Change the margins for just this video ✓ — —
Key concepts
One-time
build-index.mjs → re-render → ready
Permanent
installed skill → repackage → everyone inherits it
Repackage
always after editing the global skill
Test first
validate in a test project before applying globally

💬 Requesting the change

Claude Code understands natural language, but well-structured prompts produce more accurate and predictable results. Here are ready-to-paste templates with the information the model needs to know where e how much change — and how to validate it.

Prompt 1 — one-off visual adjustment
/* paste into Claude Code — scope: this video only */
In the next video, edit the build-index.mjs of this project:
- Enlarge the images: .folder from 520px → 620px (and 9:16 override: 440px → 520px)
- Reduce margins: .scene{padding:80px 100px 100px} (9:16: padding:140px 50px 200px)
- Add branding at the top of 9:16: element #brand-mark in .bg-layer with data-layout-ignore, centered, body.v #brand-mark{top:60px;left:50%;transform:translateX(-50%)}
- Then run: npx hyperframes inspect --samples 16 and fix any overflow
Prompt 2 — permanent global change
/* paste into Claude Code — scope: all future videos */
Edit the skill installed in ~/.claude/skills/video-explicativo/:
1. In references/house-style.md: add rule "always position the brand at the top of the 9:16 frame, centered, opacity 0.4"
2. In scripts/composition-template.mjs: increase .title from 172px → 192px and 9:16 override from 118px → 135px
3. Commit and publish the skill in the repo and confirm that the SKILL.md list the changes
Validate by creating a test video and running npx hyperframes inspect
Prompt 3 — configurable flag --brand-top
/* advanced idea: parameter in build-index.mjs */
Add at the top of the build-index.mjs:
const BRAND_TOP = process.argv.includes('--brand-top');
And in the .bg-layer CSS:
const brandCSS = BRAND_TOP ?
`body.v #brand-mark{top:60px;bottom:auto;left:50%;transform:translateX(-50%)}` : '';
/* usage: node build-index.mjs --brand-top */
🔍
Always validate with inspect + check the frames
After any layout change—specific or global—the validation workflow is always the same:
npx hyperframes render # re-renders with the changes
npx hyperframes inspect --samples 16 # audits overflow, lint, and timing
# Open a few frames in the browser and check them visually
# Publish only when inspect returns 0 issues
✓ Effective prompt
  • ✓ Specifies the file to edit
  • ✓ Specifies the CSS class and the new value
  • ✓ Mention the 9:16 override if needed
  • ✓ Asks you to run inspect at the end
✗ Vague prompt
  • ✗ "make the title bigger" — how much bigger? where?
  • ✗ "change the margins" — which file?
  • ✗ Doesn't mention whether it's one-time or global
  • ✗ Doesn't ask you to validate with inspect
Key concepts
Specificity
file + class + value = precise prompt
Explicit scope
say "this video only" or "all future ones"
--brand-top
flags configure behavior per run
always inspect
0 issues before publishing
