1.1~30 min

🧩 Qué es una Skill

Desde el primer principio: una carpeta, un archivo SKILL.md y conocimientos empaquetados que enseñan a Claude a hacer algo específico.

Qué es:

Una Skill es una carpeta cuyo nombre es el de la skill y que contiene un archivo SKILL.md. Este archivo es todo lo que se necesita para que la skill exista.

Por qué aprender:

Es el bloque elemental. Si entiendes la carpeta y el archivo, todo lo demás (refs, scripts) es solo una adición opcional.

Conceptos clave:

Carpeta = identidad; SKILL.md = instrucciones; nada más es obligatorio.

Qué es:

La skill empaqueta un procedimiento completo —pasos, reglas, ejemplos— que Claude sigue de forma coherente cada vez.

Por qué aprender:

En vez de volver a explicar un flujo en cada conversación, lo guardas una vez y queda reutilizable.

Conceptos clave:

Reutilización, consistencia, conocimiento duradero.

Qué es:

El cuerpo del SKILL.md es Markdown común: títulos, listas, bloques de código. Claude lo lee como instrucciones que debe seguir.

Por qué aprender:

Escribes en el mismo formato que ya usas para documentar, sin aprender un lenguaje nuevo.

Conceptos clave:

Markdown, instrucciones claras, pasos numerados.

Qué es:

Un prompt vive en una conversación y desaparece. Una skill queda en el disco, se puede versionar y se activa sola cuando la tarea coincide.

Por qué aprender:

Saber cuándo convertir un prompt repetido en una skill ahorra horas.

Conceptos clave:

Efímero vs. duradero; manual vs. automático.

Qué es:

Las skills pueden crear videos (HyperFrames), revisar código, diseñar interfaces, generar diagramas — cualquier flujo repetible.

Por qué aprender:

Ver la variedad te abre la mente a lo que vale la pena convertir en una skill para tu día a día.

Conceptos clave:

Flujos repetibles, dominios variados, este curso nació de una skill.

Qué es:

Crear la skill más simple no requiere programar: describes el procedimiento en texto y listo.

Por qué aprender:

Elimina la barrera de entrada: cualquier persona que escriba bien puede crear una skill útil.

Conceptos clave:

Barrera baja; empieza con texto y evoluciona después.

1.2~30 min

📝 Anatomía del SKILL.md

Todo SKILL.md empieza con dos líneas: name y description. La description es lo que Claude lee para decidir cuándo usar la skill: es el activador.

Qué es:

En la parte superior del archivo, entre --- e ---, quedan los metadatos en YAML: al menos name e description.

Por qué aprender:

Es la única parte que siempre se carga en la memoria de Claude. Si te equivocas aquí, la skill se rompe.

Conceptos clave:

YAML, delimitadores ---, metadatos.

Qué es:

O name es el identificador de la skill (kebab-case), normalmente igual al nombre de la carpeta.

Por qué aprender:

Es como tú y Claude se refieren a la skill al invocarla.

Conceptos clave:

kebab-case, único, igual que la carpeta.

Qué es:

A description dice QUÉ hace el skill y CUÁNDO usarlo. Es el texto que Claude consulta para decidir si activa el skill.

Por qué aprender:

Una Description débil hace que la skill nunca se active. Es el elemento de mayor impacto en SKILL.md.

Conceptos clave:

Disparador, «úsalo cuando…», especificidad.

Qué es:

Una buena description enumera frases concretas que activan la skill ("úsala cuando el usuario pida un video, un video explicativo, Shorts…").

Por qué aprender:

Cuanto más se parezca a la forma de hablar del usuario, más confiable será la activación.

Conceptos clave:

Frases desencadenantes, sinónimos, cubrir variaciones.

Qué es:

Después del frontmatter viene el cuerpo: el procedimiento, las reglas de oro, los comandos. Es lo que Claude ejecuta cuando se activa la skill.

Por qué aprender:

Es donde reside el valor real de la skill: cuanto más claro, mejor el resultado.

Conceptos clave:

Flujo ordenado, reglas no negociables, enlaces a refs.

Qué es:

Olvidar un ---, la indentación YAML incorrecta o una descripción demasiado vaga son los errores más comunes.

Por qué aprender:

Reconocer el síntoma ("mi skill no se activa") ahorra tiempo de depuración.

Conceptos clave:

Delimitadores, indentación, especificidad.

1.3~30 min

🧠 Divulgación progresiva

El concepto clave: Claude no carga todo de una vez. Name y description permanecen siempre en la memoria; el resto se carga solo cuando hace falta.

Qué es:

La ventana de contexto de Claude es finita. Cargar decenas de skills completas a la vez la saturaría.

Por qué aprender:

Comprender el límite explica por qué existe la divulgación progresiva.

Conceptos clave:

Ventana de contexto, costo, escala.

Qué es:

Solo el name y la description de cada skill instalada están siempre visibles para Claude: son livianos y económicos.

Por qué aprender:

Explica por qué la description debe ser tan buena: es la única señal que siempre está presente.

Conceptos clave:

Siempre activo, índice de skills, ligero.

Qué es:

Cuando la tarea coincide con la descripción, Claude abre el contenido completo de SKILL.md.

Por qué aprender:

Es el momento en que las instrucciones detalladas entran en juego, bajo demanda.

Conceptos clave:

On match, carga bajo demanda.

Qué es:

Los archivos de referencia y los scripts solo se leen cuando SKILL.md los señala y el paso los requiere.

Por qué aprender:

Permite empaquetar mucho material pesado sin costo hasta el momento de usarlo.

Conceptos clave:

On demand, referencias, scripts ejecutables.

Qué es:

Puedes tener decenas de skills instaladas y el contexto sigue siendo ligero, porque solo el índice está siempre presente.

Por qué aprender:

Es lo que hace viable una biblioteca grande de skills sin perder rendimiento.

Conceptos clave:

Escala, eficiencia, biblioteca grande.

Qué es:

Claude compara el pedido del usuario con las descriptions disponibles y elige la skill más adecuada.

Por qué aprender:

Saber esto te ayuda a escribir descriptions que «ganan» la coincidencia correcta.

Conceptos clave:

Coincidencia, relevancia, prioridad.

📂 Dónde están y cómo instalar

Las skills están en .claude/skills — en el proyecto (solo allí) o globalmente (en cualquier lugar). Instalarlo es copiar la carpeta o ejecutar un comando.

Qué es:

Una carpeta .claude/skills/ dentro del repositorio hace que el skill esté disponible solo en ese proyecto.

Por qué aprender:

Ideal para skills específicas de un producto, versionadas junto con el código.

Conceptos clave:

Alcance del proyecto, versionado y específico.

Qué es:

La carpeta global en tu directorio home (~/.claude/skills/) pone la skill a disposición en cualquier proyecto.

Por qué aprender:

Perfecto para las skills personales que usas todo el tiempo, como la de videos.

Conceptos clave:

Alcance global, reutilizable y personal.

Qué es:

Como solo es una carpeta, instalarla puede ser literalmente copiar y pegar en el lugar correcto (o descomprimir un zip).

Por qué aprender:

Es como recibiste la skill de este curso: un zip con la carpeta dentro.

Conceptos clave:

Copiar carpeta, zip, sin instalador.

Qué es:

Hay herramientas de línea de comandos que instalan skills de un catálogo con un solo comando.

Por qué aprender:

Más rápido y estandarizado cuando la skill está publicada en un registro.

Conceptos clave:

CLI, catálogo, un comando.

Qué es:

Como las skills son archivos de texto, se guardan en git como cualquier código, con historial y revisión.

Por qué aprender:

Permite hacer evolucionar la skill de forma segura y volver atrás si algo se rompe.

Conceptos clave:

Git, historial, revisión.

Qué es:

Al poner la skill en el repositorio del proyecto, queda lista para todo el equipo, con el mismo comportamiento.

Por qué aprender:

Estandariza cómo usa el equipo Claude y difunde buenas prácticas.

Conceptos clave:

Equipo, estandarización, escala organizacional.
