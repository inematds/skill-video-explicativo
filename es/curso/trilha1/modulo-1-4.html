1

📁 .claude/skills/ del proyecto

El directorio .claude/skills/ queda en la raíz de tu repositorio. Las skills allí tienen alcance local: existen solo para quienes trabajan en ese proyecto específico.

Concepto principal

El directorio .claude/skills/ en la raíz del repositorio está el espacio de skills con alcance de proyecto. Toda skill colocada allí está disponible solo cuando Claude Code se ejecuta dentro de ese repo.

Cada skill es una subcarpeta. El nombre de la carpeta es exactamente el nombre por el que Claude la reconoce; p. ej.: .claude/skills/video-explicativo/.

Estructura de directorios
# Alcance LOCAL — dentro del repositorio
mi-proyecto/
├── .claude/
│ └── skills/
│ ├── video-explicativo/ # skill de este proyecto
│ │ ├── SKILL.md # manifiesto obligatorio
│ │ ├── references/
│ │ └── scripts/
│ └── outra-skill/
├── src/
└── package.json
✓ Usa .claude/skills/ del proyecto cuando
  • ✓ La skill es específica para ese producto o cliente
  • ✓ Quieres versionar la skill junto con el código
  • ✓ Todo el equipo debe usar la misma versión de la skill
  • ✓ La skill cambia en cada sprint junto con el proyecto
✗ No uses .claude/skills/ del proyecto cuando
  • ✗ La skill sirve para todos tus proyectos personales
  • ✗ El repo es público y la skill contiene datos sensibles
  • ✗ Estás probando un borrador temporal
  • ✗ La skill debe funcionar fuera de cualquier proyecto

🌐 ~/.claude/skills/ global

El directorio global está en ~/.claude/skills/ (página principal del usuario). Las Skills que están allí se aplican absolutamente a cualquier proyecto que abras en la máquina.

🗺️ Los dos caminos lado a lado
.claude/skills/
  • • Dentro del repositorio
  • • Versionado en git
  • • Compartido con el equipo mediante clone
  • • Alcance: solo este proyecto
~/.claude/skills/
  • • En la página de inicio del usuario
  • • Fuera de cualquier repo
  • • Solo en tu máquina (no se clona)
  • • Alcance: todos los proyectos
Estructura global
# Alcance GLOBAL — directorio home del usuario
~/
└── .claude/
└── skills/
├── formato-curso/ # disponible en TODOS los proyectos
│ ├── SKILL.md
│ └── references/
└── mi-skill-personal/
💡
Precedencia: prevalece lo local

Si existe una skill con el mismo nombre en ambos lugares (local y global), la versión local (.claude/skills/) tiene prioridad. Aprovéchalo: coloca en el proyecto una versión personalizada de una skill que normalmente usas de forma global.

🌐

🏠

~/.claude/skills/
🔼
Local > Global
Override local
👤

📋 Instalar copiando la carpeta

La forma más sencilla de instalar una skill es copiar la carpeta, desde un git clone — al directorio correcto. Así es exactamente como instalas la skill video-explicativo de este curso.

Paso a paso: instalar mediante copia
1
Obtén el paquete de la skill

La skill puede venir de un repositorio propio (github.com/inematds/video-explicativo), de una carpeta comprimida o simplemente de una carpeta enviada por alguien del equipo. El contenido mínimo siempre es: SKILL.md en la raíz de la carpeta.

2
Clona el repositorio

git clone https://github.com/inematds/video-explicativo. La skill está en skills/video-explicativo/ — es esta carpeta (con el SKILL.md en su raíz) que mueves, no todo el repo.

3
Mueve al directorio correcto

Para el alcance local: mv video-explicativo/ .claude/skills/. Para el ámbito global: mv video-explicativo/ ~/.claude/skills/. Crea el directorio si no existe: mkdir -p .claude/skills/.

4
Verifica y usa

Abre Claude Code en la sesión del proyecto. La skill ya estará disponible — basta con invocarla por el nombre configurado en SKILL.md. No se necesita reiniciar ni recargar.

Comandos exactos
# Instalar skill en el proyecto actual (alcance local)
mkdir -p .claude/skills/
cp -r ~/Downloads/video-explicativo/ .claude/skills/
# Instalar globalmente (sirve en cualquier proyecto)
mkdir -p ~/.claude/skills/
cp -r ~/Downloads/video-explicativo/ ~/.claude/skills/
# Confirmar instalación
ls .claude/skills/ # lista las skills del proyecto
ls ~/.claude/skills/ # lista las skills globales
💡
Skill es solo texto — por lo tanto, es solo una carpeta

No hay binarios, no hay build, no hay dependencias npm que instalar. Una skill es 100 % archivos de texto: markdown, scripts shell, templates. Copiar la carpeta ES la instalación completa.

⌨️ Por comando

Además de copiarlas manualmente, puedes instalar skills mediante CLI, como npx skills add — que accede a un catálogo centralizado y descarga automáticamente.

Instalación desde el catálogo

Herramientas como npx skills add <nome> automatizan el proceso de copiar manualmente: buscan el paquete en el catálogo, lo descargan y lo colocan automáticamente en el lugar correcto.

Es el mismo patrón de npm install pero para skills de Claude Code: sin package.json, sin node_modules, solo la carpeta de la skill.

Ejemplo de uso
# Instalar skill del catálogo (ejemplo)
npx skills add video-explicativo
# ↑ descarga y coloca en .claude/skills/video-explicativo/
# Listar las skills disponibles en el catálogo
npx skills list
# Instalar globalmente
npx skills add video-explicativo --global
# ↑ coloca en ~/.claude/skills/video-explicativo/
# Actualizar una skill ya instalada
npx skills update video-explicativo
✓ Cuándo usar el comando
  • ✓ Skills públicas del catálogo oficial
  • ✓ Quieres garantizar la versión más reciente
  • ✓ El equipo nuevo necesita configurar el entorno rápidamente
  • ✓ Quieres explorar el catálogo de skills disponibles
✗ Cuándo NO es la mejor opción
  • ✗ Skills internas/privadas de la empresa (no publicadas)
  • ✗ Necesitas una versión personalizada específica
  • ✗ Entorno sin acceso a Internet
  • ✗ La skill todavía está en desarrollo local

🔁 Versionar en git

Una skill es texto plano, por lo que se integra de forma natural en git. Esto significa historial, diff, revisión de PR, rollback y trazabilidad completa de quién cambió qué en la skill.

💡
¿Por qué versionar la skill junto con el código?

Cuando la skill y el código evolucionan juntos en el mismo commit, siempre sabes exactamente qué versión de la skill produjo cada resultado. Nunca más "la skill cambió y el video quedó diferente" sin poder rastrearlo.

Workflow git con skill en el repo
# 1. Agregar la skill al repositorio
git add .claude/skills/video-explicativo/
git commit -m "feat: adiciona skill video-explicativo v1.0"
# 2. Ver el historial de cambios de la skill
git log --oneline .claude/skills/video-explicativo/SKILL.md
# 3. Ver qué cambió entre versiones
git diff HEAD~1 .claude/skills/video-explicativo/
# 4. Revertir la skill a una versión anterior
git checkout HEAD~1 -- .claude/skills/video-explicativo/
⚠️
¡Atención: no versioné la skill global!

Skills en ~/.claude/skills/ quedan fuera de cualquier repositorio y NO se versionan automáticamente. Si quieres una copia de seguridad o un historial de tu skill global, crea un repositorio dedicado (p. ej.: meus-skills-pessoais/) y sincroniza manualmente.

Ciclo de vida de la skill en git
1
Crea la skill

Escribe SKILL.md + referencias → git add + commit

2
Evoluciona la skill

Corrige el prompt, agrega una referencia → nuevo commit — diff visible en el PR

3
Revisión mediante PR

El equipo revisa los cambios en la skill igual que revisa el código: comentarios línea por línea

4
Etiqueta de versión

git tag v1.2-skill — congela el skill en un estado estable para producción

🔍

🤝 Compartir con el equipo

Skill en el repositorio significa que cada desarrollador que clone el proyecto recibe automáticamente las mismas skills — sin instalación manual ni divergencias entre máquinas.

El poder del estándar de equipo

Cuando la skill está en .claude/skills/ en el repositorio, cualquier git clone incluye el entorno completo. ¿Nuevo desarrollador en el equipo? Clona el repo y ya tienes la skill. ¿Máquina nueva? Clona y ya funciona.

Esto elimina la pregunta «¿qué versión del skill estás usando?» — todos usan exactamente lo que está en el commit actual del repo.

✓ Buenas prácticas para compartir
  • ✓ Documenta el skill en el README: qué es y cómo invocarlo
  • ✓ Incluye ejemplos reales de uso en el SKILL.md
  • ✓ Usa PR para cualquier cambio en la skill (revisión)
  • ✓ Mantén las referencias actualizadas cuando cambie el proyecto
✗ Trampas comunes
  • ✗ Incluir claves de API o tokens dentro de la skill en un commit
  • ✗ Skill con rutas absolutas que solo existen en tu máquina
  • ✗ Modificar la skill sin comunicar los cambios al equipo
  • ✗ Skill que depende de software no listado en los requisitos previos
📋 Lista de verificación para una nueva persona en el equipo
✓ git clone <repo>
✓ Abrir Claude Code en la raíz del proyecto
✓ Verificar ls .claude/skills/
✓ Lee el SKILL.md de la skill principal
✓ Instalar los requisitos previos indicados
✓ Probar con el ejemplo del SKILL.md
💡
Skill en el repo = documentación viva

El SKILL.md de la skill no es solo instrucciones para Claude: es documentación real de lo que usa el equipo y cómo lo usa. Mantenlo tan actualizado como mantendrías un README de una función crítica.
