🎚️ Instrucción vs. diseño: LOS DOS niveles

Toda personalización visual de un video HyperFrames ocurre en dos lugares distintos con alcances completamente diferentes. Confundirlos es la principal causa de cambios que "desaparecieron" o que "afectaron todo sin querer". Entender el modelo es el primer paso.

1
Instrucción (global) ~/.claude/skills/video-explicativo/

La skill instalada en tu entorno Claude Code. Contiene dos archivos que definen el predeterminado para cada video nuevo que Claude genere a partir de ahora:

references/house-style.md
Estilo, paleta, fuentes, proporción, reglas de composición. Todo en prosa. Claude lo lee e interpreta al generar el build-index.mjs.
scripts/composition-template.mjs
La plantilla de código con CSS completo, clases (.title, .h2, .scene…), overrides 9:16 y estructura de escenas.
2
Diseño (local) projeto/build-index.mjs

La copia generada en el proyecto específico. Es el CSS/HTML concreto de ese render. Modificarlo afecta solo ese video — rápido, sin consecuencias globales.

Regla de oro
Mover la instrucción cambia todo a partir de ahora (todos los videos nuevos). Modificar el layout cambia solo ese video.
💡
Consejo práctico
Antes de editar cualquier archivo, pregúntate: «Quiero que esto cambie en todos ¿o dejarlo para los próximos videos o solo para este?" Si la respuesta es "solo para este", toca solo el build-index.mjs del proyecto. Si es «en todos», edita el skill instalado — y recuerda hacer commit y publicar en el repo da skill.
Conceptos clave
Instrucción
house-style + template = estándar global
Diseño
build-index.mjs = CSS/HTML concreto local
Alcance
global vs local — decide siempre primero
Volver a empaquetar
obligatorio al cambiar el skill instalado

🔠 Tamaño de los elementos

O composition-template.mjs define los tamaños base para 16:9. Hay un bloque de overrides 9:16 (prefijo body.v) que redimensiona todo al formato vertical. Conocer las clases y los valores concretos te permite hacer ajustes precisos.

Tamaños base — 16:9 (composition-template.mjs)
Clase Propiedad Valor 16:9 Override 9:16
.title font-size 172px 118px
.h2 font-size 92px 74px
.lead font-size 34px 30px
.folder width / height 520px / 360px 440px / 300px
.code width auto 940px
.file-card font-size / top / left 36px / 120px / 110px 30px / 110px / 96px
.subhead font-size 40px 34px
Bloque real de composition-template.mjs — clases base 16:9
/* composition-template.mjs — tipografía y tarjetas base */
.title{font-family:Sora,sans-serif;font-weight:800;font-size:172px;line-height:.95;letter-spacing:-.03em;margin:24px 0}
.subhead{font-size:40px;color:var(--muted)}
.h2{font-family:Sora,sans-serif;font-weight:800;font-size:92px;line-height:1.05;letter-spacing:-.02em}
.lead{font-size:34px;color:var(--muted);margin-top:28px;line-height:1.4}
/* carpeta */
.folder{position:relative;width:520px;height:360px;margin:0 auto}
/* overrides 9:16 */
body.v .title{font-size:118px;margin:20px 0}
body.v .h2{font-size:74px}
body.v .lead{font-size:30px;margin-top:24px}
body.v .folder{width:440px;height:300px}
🔼
Cómo agrandar un elemento
Ubica la clase en el build-index.mjs del proyecto y aumenta el valor. Para .title de 172px → 200px, por ejemplo:
- .title{font-size:172px}
+ .title{font-size:200px}
/* y el override 9:16, si quieres mantener la proporción: */
- body.v .title{font-size:118px}
+ body.v .title{font-size:138px}

body.v

Proporción
ajuste base y override en la misma escala
Ubicar

📐 Márgenes de seguridad

O .scene es el contenedor de cada escena. Su padding define el espacio entre el contenido y el borde del frame — el "margen de seguridad". Disminuirlo = full-bleed; aumentarlo = más espacio para respirar.

16:9 (horizontal)
.scene{
/* arriba derecha abajo izquierda */
padding:120px 150px 150px;
}
Parte superior: 120px, laterales: 150px, parte inferior: 150px. Buen equilibrio para 1920×1080.
9:16 (vertical / Shorts)
body.v .scene{
/* arriba derecha abajo izquierda */
padding:170px 70px 240px;
}
Parte superior: 170px (rostro en cámara), laterales: 70px, parte inferior: 240px (pulgar + UI). Nunca reduzcas la parte inferior a menos de 180px en Shorts.
El subtítulo tiene su propio margen, separado del padding de .scene
.caption{bottom:64px} /* 16:9 */
body.v .caption{bottom:150px} /* 9:16 — por encima de la barra de UI */
Al reducir el padding del .scene para que ocupe toda la pantalla, el subtítulo puede desbordarse. Ajusta .caption{bottom} proporcionalmente.
⚠️
Atención: overflow invisible
Reducir demasiado el padding puede hacer que los elementos salgan del canvas sin que te des cuenta en la vista previa. Siempre ejecuta npx hyperframes inspect --samples 16 después de cambiar los márgenes. La auditoría señalará un desbordamiento si detecta contenido fuera de los límites.
✓ Buenas prácticas
  • ✓ Mantén bottom ≥ 120px en 16:9
  • ✓ Mantén bottom ≥ 180px en 9:16 (Shorts UI)
  • ✓ Ajustar .caption{bottom} al cambiar el padding
  • ✓ Ejecutar inspect después de cada cambio
✗ Evitar
  • ✗ Padding cero o negativo
  • ✗ Ignorar la leyenda al pasar a full-bleed
  • ✗ Cambiar solo 16:9 y olvidar el override 9:16
  • ✗ Publicar sin ejecutar inspect
Conceptos clave
.scene padding
120/150/150 (16:9) · 170/70/240 (9:16)
.caption bottom
64px 16:9 · 150px 9:16
overflow
invisible en la vista previa, visible en inspect
full-bleed
reduce el padding, pero siempre valida

🏷️ Posición de la marca

A veces quieres un elemento de marca persistente —un logo, una marca de agua, una insignia— que aparezca en todas las escenas sin entrar en la lógica de escenas/tweens. El patrón es agregar ese elemento en el .bg-layer (capa de fondo persistente) con data-layout-ignore y posicionarlo mediante CSS, con override body.v para el formato vertical.

ℹ️
La CTA ya existe: no la reinventes
La escena final (scene9) siempre muestra la CTA INEMA.CLUB como cierre obligatorio del video. Cubre la "marca final". El elemento persistente que estamos creando aquí sirve para identificación discreta durante el video — como una marca de agua en una esquina.
Snippet: elemento de marca persistente en .bg-layer
/* build-index.mjs — dentro de .bg-layer, después de los elementos existentes */
/* 1. Añade el elemento con data-layout-ignore */
<div id="brand-mark"
data-layout-ignore="true"
style="position:absolute;bottom:40px;right:50px;opacity:0.35;pointer-events:none;">
<img src="brand/logo.svg" width="120" alt=""/>
</div>
/* 2. CSS: posición base (16:9) + override 9:16 */
#brand-mark{
position:absolute;bottom:40px;right:50px;
opacity:.35;pointer-events:none;
}
body.v #brand-mark{
/* 9:16: marca arriba, centrada */
top:60px;bottom:auto;left:50%;right:auto;
transform:translateX(-50%);opacity:.45;
}
🔑
Por qué data-layout-ignore es obligatorio
El auditor de HyperFrames mide el cuadro delimitador de cada elemento para detectar desbordamientos. Un elemento de marca fuera de los límites predeterminados dará un falso positivo, a menos que lo marques con data-layout-ignore="true". Con este atributo, el auditor ignora el elemento al contar el overflow.
Conceptos clave
.bg-layer
capa persistente — aparece en todas las escenas
data-layout-ignore
excluye de la auditoría de overflow
body.v override
posición diferente en 9:16 (parte superior centrada)
CTA scene9
INEMA.CLUB ya es el cierre — no lo dupliques

🔁 Puntual vs. permanente

Antes de cualquier edición, decide el alcance. La pregunta es simple: este cambio solo aplica a este video o para todos los próximos? La respuesta determina qué archivo tocas y cuánto trabajo te llevará.

P Puntual — 1 video
Edita el build-index.mjs del proyecto y vuelve a renderizar.
✓ Rápido — 1 archivo, 1 render
✓ Sin riesgo de afectar otros proyectos
✓ No requiere volver a empaquetar la skill
✗ El siguiente video no hereda el cambio
Cuándo usar
  • • Ajuste fino del color para una campaña
  • • Prueba de un nuevo diseño de card
  • • Override de fuente para un cliente
  • • Corrección de proporción en un frame específico
G Permanente — todos
Edita house-style.md + composition-template.mjs en la skill instalada y vuelve a empaquetar.
✓ Todos los videos nuevos heredan
✓ Mantiene la coherencia de marca
✗ Exige commit + push en el repo de la skill
✗ Más impacto: probar antes
Cuándo usar
  • • Cambiar la paleta de colores del canal
  • • Adoptar una nueva tipografía estándar
  • • Agregar un elemento de marca en todos
  • • Ajustar los márgenes globales de seguridad
Cuadrícula de decisión: ¿qué archivo editar?
Situación build-index.mjs house-style.md composition-template.mjs
Cambiar el color de un solo video ✓ — —
Cambiar la fuente predeterminada de todos — ✓ ✓
Aumentar .title en este proyecto ✓ — —
Aumentar .title en todos los videos — — ✓
Agregar una marca persistente global — ✓ ✓
Cambiar los márgenes solo de este video ✓ — —
Conceptos clave
Puntual
build-index.mjs → re-render → listo
Permanente
skill instalado → volver a empaquetar → todos heredan
Volver a empaquetar
siempre después de editar la skill global
Probar antes
valídalo en un proyecto de prueba antes de aplicarlo globalmente

💬 Solicitar el cambio

Claude Code entiende el lenguaje natural, pero los prompts bien estructurados producen resultados más precisos y predecibles. Aquí tienes templates listos para copiar y pegar, con la información que el modelo necesita para saber dónde e cuánto modificar, y cómo validarlo.

Prompt 1 — ajuste visual puntual
/* pega en Claude Code — alcance: solo este video */
En el próximo video, edita el build-index.mjs de este proyecto:
- Aumenta las imágenes: .folder de 520px → 620px (y override 9:16: 440px → 520px)
- Reduce los márgenes: .scene{padding:80px 100px 100px} (9:16: padding:140px 50px 200px)
- Agrega la marca en la parte superior de 9:16: elemento #brand-mark en .bg-layer con data-layout-ignore, centrado, body.v #brand-mark{top:60px;left:50%;transform:translateX(-50%)}
- Después ejecuta: npx hyperframes inspect --samples 16 y corrige cualquier overflow
Prompt 2 — cambio global permanente
/* pega en Claude Code — alcance: todos los videos futuros */
Edita la skill instalada en ~/.claude/skills/video-explicativo/:
1. En references/house-style.md: agrega la regla "marca siempre en la parte superior del 9:16, centrada, opacity 0.4"
2. En scripts/composition-template.mjs: aumenta .title de 172px → 192px y override 9:16 de 118px → 135px
3. Confirma el commit y la publicación del skill en el repo y que el SKILL.md enumera los cambios
Valida creando un video de prueba y ejecutando npx hyperframes inspect
Prompt 3 — indicador configurable --brand-top
/* idea avanzada: parámetro en build-index.mjs */
Agrega al inicio del build-index.mjs:
const BRAND_TOP = process.argv.includes('--brand-top');
Y en el CSS de .bg-layer:
const brandCSS = BRAND_TOP ?
`body.v #brand-mark{top:60px;bottom:auto;left:50%;transform:translateX(-50%)}` : '';
/* uso: node build-index.mjs --brand-top */
🔍
Valida siempre con inspect + revisa los fotogramas
Después de cualquier cambio de diseño — puntual o global — el flujo de validación es siempre el mismo:
npx hyperframes render # vuelve a renderizar con los cambios
npx hyperframes inspect --samples 16 # audita overflow, lint, timing
# Abre algunos fotogramas en el navegador y revísalos visualmente
# Publica solo cuando inspect devuelva 0 problemas
✓ Prompt eficaz
  • ✓ Especifica el archivo que se editará
  • ✓ Indica la clase CSS y el nuevo valor
  • ✓ Menciona el override 9:16 si es necesario
  • ✓ Pide ejecutar inspect al final
✗ Prompt vago
  • ✗ "haz el título más grande" — ¿cuánto? ¿dónde?
  • ✗ "cambia los márgenes" — ¿qué archivo?
  • ✗ No menciona si es puntual o global
  • ✗ No pide validación con inspect
